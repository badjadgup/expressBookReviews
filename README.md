# Express Book Review final project

Working Node.js / Express implementation based on IBM's public starter:
https://github.com/ibm-developer-skills-network/expressBookReviews

## Finish the GitHub requirement first

The assessment text calls the repository `expressBookReview`, but IBM's public
starter is named **expressBookReviews** (plural). Use the starter linked above.

1. Sign in to GitHub, open that starter, and click **Fork → Create fork**.
   Keep your fork public so a grader can view it. An ordinary new empty repository
   does not satisfy the fork requirement.
2. On YOUR fork, choose **Add file → Upload files**. Upload the **contents** of
   this folder, with `final_project`, `scripts`, and the evidence files at the
   repository root. Do not upload the containing `expressBookReviews` folder as
   an extra directory. Commit your changes to your fork.
3. Locally, open a terminal inside `final_project` and run:

   ```powershell
   npm ci
   node ../scripts/capture-github.js YOUR_USERNAME/YOUR_FORK_NAME
   ```

   Replace `YOUR_USERNAME/YOUR_FORK_NAME` with the actual fork, for example
   `badjadgup/expressBookReviews` if that is the fork you create. The script
   checks the public GitHub API for `fork: true` and the correct `parent.full_name`.
   Only then does it replace `githubrepo` with the actual cURL command and output,
   and write the Q11 link into `general-url.txt`.
4. Upload the regenerated `githubrepo` and `general-url.txt` to your fork as well.
5. Open the link in `general-url.txt` to confirm the code is public before submitting.

**Current status:** Q2-Q10 evidence was generated by executing real cURL requests
against this application. Q1 and the public Q11 URL require your public fork and
upload. The current `githubrepo` and `general-url.txt` are clearly marked setup
notes, not fabricated proof. Do not submit their pending text.

## Run and verify

Requires Node.js 22 or newer and cURL on PATH. From `final_project`:

```powershell
npm ci
node --test test/api.test.js
node index.js
```

The API listens on http://127.0.0.1:5000. Stop it with Ctrl+C.
Equivalent npm scripts are `npm test` and `npm start`; direct Node commands are
provided for environments with shell configuration problems.

To regenerate Q2-Q10, stop the running server first, then from `final_project`:

```powershell
node ../scripts/capture-evidence.js
```

This starts a fresh server on port 5000, runs cURL, writes the nine evidence files
at the repository root, removes its temporary cookie file, and stops the server.
The transcript commands assume the repository root as the working directory.
On macOS/Linux the script uses `curl`; on Windows it uses `curl.exe` to avoid
PowerShell's legacy `curl` alias.

## Axios implementation for Q11

`final_project/router/general.js` includes both the public Express routes and:

- `getAllBooks(callback?, client?)`: Axios with async/await and an optional callback.
- `getBooksByISBN(isbn, client?)`: Axios with a promise `.then()` callback.
- `getBooksByAuthor(author, client?)`: Axios with async/await.
- `getBooksByTitle(title, client?)`: Axios with async/await.

The tests execute all four functions against a real running local HTTP server,
including a title containing spaces and missing-book rejection paths. The Axios
functions run on the client side of the API; Express handlers read `booksdb.js`.
This separation avoids an endpoint requesting itself in a loop.

Authentication tests also cover duplicate registration, wrong passwords, blocked
anonymous writes, review validation, and two users independently managing their
own reviews without deleting each other's work.

## Scope and provenance

The starter's `booksdb.js` and Apache-2.0 `LICENSE` are retained. The starter's
unfinished routes have been implemented, with a delete endpoint, Axios clients,
tests, capture scripts, and a dependency lockfile added. This is a local course
project: users, sessions, and reviews are stored in memory and reset on restart.
Passwords are salted and hashed. Demo credentials under `scripts/payloads` are
public examples, not real account credentials. Session cookies and JWTs are not
included in the saved evidence.

Validation: both integration tests passed; all Q2-Q10 cURL responses returned
their expected HTTP status. The installed dependency audit reported zero
vulnerabilities at preparation time. Review and understand the implementation
before submitting, and follow your course's rules for assisted work.
